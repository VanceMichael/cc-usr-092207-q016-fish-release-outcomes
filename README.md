# 珍稀鱼类放流成效核验

核验珍稀鱼类从繁育放流到野外再发现和自然繁殖的成效。多年累计放流七百多万尾只代表投入量，真正要回答的是：**哪些遗传批次活了下来、扩散到了哪里、新发现个体来自人工投放还是自然繁殖**。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例，`src/domain.py` 在结构契约之外做语义校验。当前参与方包括鱼类保育中心、放流执行单位、第三方生态监测人员、流域保护决策人员、科研分析人员。

资料所依据的领域事实如下：

- 四川建有长江鲟保育中心并保存大量野生原种
- 金沙江上游多年累计放流珍稀特有鱼类苗种
- 监测中出现鱼类种类回升和长江鲟自然繁殖进展

## 资料结构与原则

1. **连续血缘（`custody_chain`）**：亲本建档 → 繁育检疫 → 标记 → 运输容器封签 → 现场计数 → 按批次放流 → 河段水文与后续采样，七个阶段缺一不可且顺序固定，每阶段只能由具备对应职责的参与方承担。批次可向上追溯到具体亲本，放流记录引用批次、容器、河段与水文原始观察。
2. **原始观察只追加不修改（`observations[].immutable`）**：标签脱落、重复捕获、计数纠正、异常死亡都只能新增记录。计数纠正通过 `corrects` 指向被纠正的原始观察，且记录时间不得早于原始观察；原始观察删除即视为改写历史，校验直接拒绝。
3. **概率识别留方法与置信度（`origin_assignments`）**：每尾再发现都必须有来源判定（人工批次/自然野生/不可区分），记录方法、置信度和出具分析人员。标记疑似脱落时要显式假设；混合样本（如 eDNA）只能给群体级后验与置信区间，禁止逐尾指认。
4. **分析换版不改观察（`analyses`）**：标签脱落校正、重捕去重、计数纠正、异常死亡、混合样本概率化等只能在分析层声明为 `adjustments`；输入中出现对应类型的观察就必须声明对应调整，不允许静默修正。监测方案换版（如 MP-v3.1→v3.2 纳入 eDNA）必须给出原因，旧版本保留为 `superseded`，任何时刻有且仅有一个 `current` 版本。
5. **指标可复算（`analyses[].metrics`）**：存活率、扩散距离等指标必须给出公式，且输入只能来自该分析已声明的原始观察，第三方科研人员可据此独立复算。
6. **职责分离提交证据**：保育中心提交亲本、检疫、标记证据；放流单位提交运输与现场计数；第三方监测提交采样、重捕、异常死亡与产卵场发现；决策方不生产证据，只依据 `current` 分析作年度决策。
7. **年度决策（`decisions`）**：必须同时覆盖物种、数量、放流河段三个维度的调整，并显式声明对自然繁殖的结论。
8. **自然产卵证据边界（`natural_spawning_evidence`）**：卵/幼鱼需遗传排除全部放流批次、跨日重复出现、排除养殖逃逸；仅有 eDNA 或带标亲鱼产卵均不计为自然繁殖确证。示例数据中的信号为"未确证"，年度决策不得据此宣称自然繁殖已建立。
